OBS display capture vs window capture, and what Game Bar and Snipping Tool actually record

2026 · ~6 min read · OfferPilot AI

Display Capture takes the finished image of one monitor, so it records everything on that panel: every window, the taskbar, notification toasts, the Start menu, your cursor. Window Capture takes one window's own drawing buffer, so it records that application alone and keeps recording it perfectly even when the window is buried behind three others. Game Capture hooks an application's graphics API and records only the frames that application renders. Xbox Game Bar is app-scoped like Game Capture; Snipping Tool records a fixed rectangle of the display, which makes it a cropped Display Capture. One window can be missing from all five at once, and that is a Windows feature rather than a bug.

Why a completely buried window still records perfectly

Window Capture surprises anyone who assumes a recorder photographs the screen. It does not. Since Windows Vista, the Desktop Window Manager has given every top-level window its own off-screen buffer, and the monitor shows DWM's composite of those buffers. A window sitting behind four others is still drawing into its buffer at full size. Window Capture reads that buffer, so the file shows a clean, unobstructed window while your actual screen shows almost none of it.

The mechanics differ by method, and OBS puts the choice in the source properties:

  • Windows Graphics Capture asks DWM for the window's composition surface. It handles hardware-accelerated windows such as Chrome and Electron apps, which is most software now. Older Windows 10 builds draw a coloured border around the captured window on your own screen; recent Windows 11 builds let OBS switch that border off.
  • BitBlt is the legacy path, effectively asking the window to paint itself into a device context. Cheap and border-free, but it returns black for many GPU-composited windows, which is the classic "Chrome records as a black box" symptom.

Two limits. Minimising is not the same as covering: a minimised window is not composited at all, so capture freezes on the last frame or goes black. And some applications detect that they are occluded and stop rendering to save power, so there are no frames to read. Games and some Electron apps do exactly that.

One detail quietly ruins recordings. OBS matches a window by title, class and executable through the Window Match Priority dropdown. Leave it on title-matching against a browser and the source drops the moment the tab title changes, because the window it was watching no longer exists under that name. Set it to match the title and otherwise find a window of the same executable.

Why Display Capture is the only mode that gets everything

Display Capture reads the composited output of the monitor itself, through DXGI Desktop Duplication or the Windows Graphics Capture monitor path. There is no per-window concept in that frame, so anything DWM drew on the panel is in it, including the surfaces nobody thinks of as windows: notification toasts, the Alt-Tab thumbnail strip, tooltips, drag ghosts, the Start menu, the volume flyout, unread badges on taskbar icons. It has two known holes. The UAC consent prompt runs on a separate secure desktop, so an unelevated OBS records a frozen or missing prompt. And a wholly black Display Capture on a laptop is nearly always a GPU mismatch.

Try each capture method explicitly

Right click the source, Properties, then step through Capture Method instead of leaving it on Automatic. DXGI Desktop Duplication and the Windows 10 or 11 method fail in different situations.

Check which GPU OBS runs on

Settings, System, Display, Graphics. For Display Capture set OBS to Power saving so it runs on the integrated GPU that composites your desktop. For Game Capture, High performance is correct. This fixes most black display captures on dual-GPU laptops.

Rule out DRM before blaming OBS

If only the video player is black and everything around it records fine, that is protected playback working as designed. No capture setting changes it.

Record ten seconds and open the file

The OBS preview is not the deliverable. Play the MP4 back. Clipped menus and dropped sources show up there and nowhere else.

Why an excluded window is missing from every recorder at once

Windows lets an application call SetWindowDisplayAffinity on its own window. With the WDA_EXCLUDEFROMCAPTURE flag, available since Windows 10 build 19041, DWM composites that window to your physical display but strips it from the frames it hands to capture APIs. The exclusion happens before OBS, Game Bar, Snipping Tool or Zoom receive a single pixel, which is why one flag knocks the window out of all of them at the same time rather than needing a per-app trick. Display Capture records the desktop behind it. Point Window Capture straight at it and you get black or an empty source. The older WDA_MONITOR flag leaves a visible black rectangle instead, so "black box" and "not there at all" tell you which flag an app uses.

OfferPilot AI uses that flag for its overlay, so the overlay stays readable on your own monitor while being absent from OBS in all three modes, from Game Bar, from Snipping Tool, from a plain screenshot, and from Zoom, Teams and Meet. The same applies to the screenshot flow in Code Copilot: the selection rectangle you drag after Ctrl+Alt+S belongs to the excluded surface, so it does not appear in a recording of the same screen. Capture exclusion is on every plan including the free one, so you can verify it rather than take anyone's word for it.

Where this stops being true

Capture exclusion is a compositor feature, not invisibility. It applies only to software that asks Windows for the screen. It does nothing about anything looking at your monitor from outside the machine: a webcam or a proctor watching you live, a phone propped up as a second camera, a hardware capture card between your GPU and your display, eye tracking, or a lockdown browser that takes over the whole machine. If a round is proctored under rules you have agreed to, no capture behaviour changes what those rules say, and OfferPilot is the wrong tool there. It is Windows 10 and 11 only, with no macOS, Linux, mobile or browser-extension build.

Two caveats on the table itself. Game Bar's scope has shifted across Windows 11 builds as Microsoft widened what counts as a recordable app, so if yours records something this page says it will not, trust your machine. And OBS reshuffles capture method names between major versions while the underlying behaviour stays far more stable than the labels. Where your properties dialog disagrees with this text, the dialog wins.

If you are picking a mode because you want to know what an interviewer's recording would contain, there is a faster test than any table.
