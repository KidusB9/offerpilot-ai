Can proctoring software detect a second monitor?

2026 · ~7 min read · OfferPilot AI

Yes, an installed proctoring client detects a second monitor trivially, and a browser based one usually can too. It does not do this by looking at your screens. It asks the operating system how many displays are attached and reads back a list, which is an ordinary, unprivileged call that raises no prompt and takes microseconds. The interesting questions are not whether it can see the monitor, but when it checks, whether it blocks or merely flags, and which desk arrangements produce a count that surprises you.

Display enumeration, the mechanism behind the whole question

Every desktop operating system maintains a register of attached displays so that ordinary software can lay windows out correctly, and it hands that register to any application that asks. On Windows the call is EnumDisplayMonitors, or GetSystemMetrics with the monitor count constant, or the managed equivalent Screen.AllScreens. On macOS it is NSScreen.screens. Each entry carries a device name, a rectangle giving that panel's size and its position in the virtual desktop, and a flag marking the primary. None of that is surveillance, it is the same information a photo editor uses to remember which monitor you left it on. The consequence is the part candidates get wrong: the software never needs to see the second screen's contents to know it exists. Detecting the panel and capturing the panel are separate capabilities with separate permissions, and enumeration is the cheap one. There is no dialog to decline, no camera involved, and nothing you can turn off inside the app. If a second display is attached, the list has two rows in it.

Run the exact query a proctoring client runs

You can read your own list in about fifteen seconds and see precisely what would be reported about your hardware. Open Windows PowerShell and run these two lines:

  • Add-Type -AssemblyName System.Windows.Forms
  • [System.Windows.Forms.Screen]::AllScreens | Select-Object DeviceName, Primary, Bounds

On the two monitor machine this page was written on, that printed \\.\DISPLAY1, primary true, bounds starting at X=0, then \\.\DISPLAY5, primary false, bounds starting at X=1536. Two details in that output are worth keeping. The device names are not 1 and 2, they are 1 and 5, because Windows keeps stale slots for panels that were once attached, so a name is never a reliable count. And the bounds are logical coordinates affected by display scaling rather than native pixels, which is why a 4K panel can report as something much smaller. The X offset is the second useful signal: a non zero or negative X on any entry is the arithmetic that tells a client your desktop spans more than one panel.

For the browser case, press F12 and type screen.isExtended in the Console. In Chromium browsers that returns a boolean with no prompt at all, and true means more than one display is attached. The sizes and labels sit behind a window management permission you would see and could refuse. The boolean you cannot refuse.

What your desk looks like versus what the count returns

The count is not a headcount of lit panels, and the gaps run in both directions. This is where honest surprises happen, including flags on setups the candidate considered single monitor.

Physical arrangementWhat enumeration returnsPractical consequence
Laptop panel plus one external, set to ExtendTwo displays, with distinct boundsThe plain case. Detected, and flagged wherever a single display rule exists.
Laptop closed in a dock, one external screenOne displayGenuinely a single display setup. The internal panel is off, not merely ignored.
Two panels set to Duplicate or mirrorOne displayNot a loophole. One desktop painted twice means everything on the spare panel is already inside any screen share, and a room scan still sees two lit screens.
Spanned mode such as NVIDIA Surround or AMD EyefinityOne display at an unusual resolutionA single entry reading 5760 by 1080 is its own anomaly, and a capture of that one display contains all three panels.
HDMI dummy plug or a virtual display adapterAn extra display with no physical panelCounted like any other. It adds to the number rather than hiding anything.
Remote desktop, streaming or capture tools that install a virtual display driverA phantom display that you cannot seeThe most common false positive. Worth checking before an exam rather than arguing about afterwards.
A TV or projector left connected to a dock, screen offVaries by cable and monitorWhether a powered off panel drops out of the list depends on the connection, so unplug the cable rather than trusting the power button.

That last row is the practical instruction hiding in this table. If a rule says one display, disconnect at the cable. Switching a monitor off is a change in the monitor, not necessarily a change in the list the operating system publishes, and the only way to know which your hardware does is to run the check above with the panel off.

Detecting is not the same as blocking

Software that can count displays chooses what to do about it, and the choices differ enormously by product tier.

A hard gate at launch

Lockdown clients and remote certification exams typically check before the first question and refuse to start, telling you to disconnect. This is the friendliest failure mode, because it happens while nothing is at stake and the timer has not started.

A recorded fact in a report

Browser based proctoring more often logs the configuration and moves on. The multi display note lands in a session report a reviewer reads later, next to focus changes and camera stills, and it is context rather than a verdict on its own.

A continuous watch, not a single snapshot

Windows broadcasts a message when the display configuration changes, so a resident client can be told about a monitor plugged in mid session without polling for it. Unplugging for the launch check and reconnecting once the test is running is therefore a timestamped event, which reads far worse than the original configuration would have.

No check at all

Plenty of unproctored employer tests and every live shared editor session enumerate nothing, because there is no agent on your machine to do it. Here the only observer is a human watching your pointer and your eyes.

Work out which of those four you are in first, because it changes what matters. The way to find out is not a general article, it is the rules screen on your own invite, searched for the words monitor, display and screen.

What a display count still does not reveal

Enumeration is a list of panels, not a view of them. Knowing a second monitor exists tells the software its resolution, its position and its name, and nothing about what is drawn on it. Reading pixels needs a separate capture grant, which on the web is the share prompt you click through. So a session can know you have two displays and hold no image of the second one. That cuts both ways. The count is a rules question rather than an evidence question, and a setup that looks clean in the list can still be exposed by the webcam, which watches your eyes rather than your hardware. Sustained sideways gaze at something outside the frame is a far more commonly reported trigger for human review than any display count.

The short version

  • Yes, and without looking. The operating system publishes the display list to any application that asks, so the count is available without a prompt, a camera or a single captured pixel.
  • Check your own list first. Two lines of PowerShell show you exactly what would be reported, including phantom displays from virtual display drivers that you did not know were there.
  • Disconnect at the cable, before launch. A powered off panel may still enumerate, and reconnecting mid session is an event with a timestamp on it.
  • The count is a rules question. Detection tells them a panel exists. Whether that matters is written on your invite, so read it rather than guessing.
